## 2. 已确认的关键技术决策（ADR）

> 这些决策是各设计篇的共同前提，任何变更都应在本文档同步更新。

| 编号 | 决策项 | 结论 | 理由 |
|---|---|---|---|
| ADR-01 | 交付形式 | `docs/` 独立分篇，中文 | 便于分工维护与版本管理 |
| ADR-02 | 编译器实现语言 | Kotlin | JVM 生态、协程适合并行编译、自身即 JVM 依赖 |
| ADR-03 | 解析器技术 | 手写递归下降 | 无代码生成依赖、报错可控、适合 Yux 极简语法 |
| ADR-04 | 字节码生成 | ASM 直接生成 JVM 字节码 | 无中间源码层，性能与调试一致 |
| ADR-05 | 块与语句分隔 | `{}` + 换行分隔，分号可选 | Kotlin/Go 式，极简 |
| ADR-06 | 字符串插值 | `$` 美元符（`$name` / `${expr}`） | 与 Kotlin/Shell 一致 |
| ADR-07 | Lambda | 箭头 `x -> ...`，支持隐式 `it` | 简单可预测 |
| ADR-08 | 类型推断 | 局部双向推断，函数参数显式类型 | 简单可预测，适合手写编译器 |
| ADR-09 | 泛型语法 | `List String`（无尖括号） | 更易读，避免嵌套解析歧义 |
| ADR-10 | 空安全 | 编译提醒 + 运行保护 | 避免 Kotlin 过度严格 |
| ADR-11 | Minecraft 扩展 | 编译器插件 API（非内置关键字） | 符合 Design.md「非语言本体」定位 |
| ADR-12 | 构建方式 | `build.yml` → 生成 Gradle 脚本 → 调用 Gradle | 复用成熟构建生态 |
| ADR-13 | 规范深度 | 完整 EBNF + 语义规则 + 示例 | 可作为编译器实现依据 |
| ADR-14 | 编译器覆盖范围 | 完整架构（含未来 Native 预留） | 一次定架构，避免返工 |

## 4. 全局术语表

| 术语 | 定义 |
|---|---|
| **Yux 源码** | `.yux` 文件，一个文件通常对应一个顶级类型或一组顶层函数 |
| **顶级对象** | 文件中顶层声明（类/`data`/`service`/函数），默认为类 |
| **IR** | Yux 编译器中间表示，位于语义分析之后、各后端之前 |
| **编译器插件** | 通过 `yux-plugin-api` 扩展词法/语法/语义的组件，如 `yux-compiler-minecraft` |
| **YuxPlugin SDK** | 面向 Minecraft 的完整开发套件 = 语言扩展插件 + 运行时库 |
| **运行时库** | 编译产物依赖的 JVM 库，如 `yux.core`、`yux.minecraft` |
| **属性（Property）** | 类字段 + 自动生成的 getter/setter（可自定义） |
| **局部推断** | 仅基于初始化表达式与上下文的双向推断，不做全局 HM 推断 |

## 5. 写作约定

- 文档语言：中文；代码示例一律 `Yux`/`Java`/`Kotlin` 对照。
- EBNF 记号约定：
  - `A ::= B C` 顺序
  - `A | B` 选择
  - `[X]` 可选
  - `{X}` 重复零次或多次
  - `X+` 至少一次
  - 终结符用 `'x'` 或等宽字；非终结符用 `Name`
- 语义规则在 EBNF 之后逐条列出，编号 `S-xx`，便于编译器文档引用。
- 语法用 `.yux` 代码块标注，EBNF 用 `ebnf` 代码块标注。
